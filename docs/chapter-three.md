## §3.1 Banana-split: deriving one traversal from two

To compute the average of a list of natural numbers, we need its sum and length. Specify the intermediate result as `stats xs = (sum xs, length xs)`. Derive the fold by asking what this pair must do at each constructor:

```text
stats []       = (0, 0)                            definitions of sum and length
stats (a ∷ xs) = (sum (a ∷ xs), length (a ∷ xs))    specification
               = (a + sum xs, suc (length xs))      unfold both list folds
               = step a (sum xs, length xs)         step a (s,n) = (a+s, suc n)
               = step a (stats xs)                  specification on the tail
```

These are the equations of a single right fold. In [Average](../src/AoP/Chapter03/Average.agda), `layer-law` checks the constructor cases and `split` proves agreement with the pair of separate folds. Only after the traversal do we interpret the result as a ratio; the chosen convention for an empty list is `0/1`. In the [steep-list test](../src/AoP/Chapter03/Steep.agda), the Boolean result for the head also uses the sum for the tail. That dependence is why the auxiliary-fold law in exercise 3.4 is useful.

## §3.2 Ruby triangles and Horner’s rule

Suppose the coefficients start with the constant term. One evaluation strategy builds a list in which each coefficient has been scaled by `x` once for each earlier coefficient, then sums the list. Write `T` for that triangle, `scale a = a * x`, and `H as = sum (T as)`. Derive the update rather than constructing the triangle:

```text
H []       = 0                                      empty triangle and sum
H (a ∷ as) = sum (a ∷ map scale (T as))             triangle step
           = a + sum (map scale (T as))             sum step
           = a + scale (sum (T as))                 push scaling through sum
           = a + scale (H as)                       specification on the suffix
```

The third equality uses two laws: `scale 0 = 0` for an empty sum, and `(b+c)*x = b*x + c*x` for a cons step. [Horner](../src/AoP/Chapter03/Horner.agda) derives the rule from those laws. [HornerPolynomialTrace](../src/AoP/Chapter03/HornerPolynomialTrace.agda) compares both computations at `x = 10`: the triangle for `[2,3,4]` is `[2,30,400]`; the fused fold starts at `0` and updates to `4`, `43`, then `432`. Exercise 3.14 applies the same idea to depths in a tree.

## §3.3: decimal input for TeX

[Worked rounding calculation](tex-rounding.md): the integer states for `.25`, a midpoint where sixteen digits fail, and the grid argument for retaining seventeen digits.

Given decimal digits after the point, return the nearest count of units of size `1/65536`, rounding ties upward. [TeXFraction](../src/AoP/Chapter03/TeXFraction.agda) folds the digits from the right with one extra binary digit of precision, then rounds once. Its refinement from exact valuation assumes the floor-and-shift identity. For example, `.00007` and `.00008` both round to 5 units, but prefixing a zero makes their rounded values differ.

## §3.4: conditions and conditionals

[Conditions](../src/AoP/Chapter03/Conditions.agda) distributes an input paired with a Boolean tag into two branches. Both branches retain the input. The calculation of equation 3.3 moves a function after a conditional into both branches. [BranchTags](../src/AoP/Chapter03/BranchTags.agda) checks the precomposition and equal-branch equations 3.4–3.5 pointwise. [ConditionalFusion](../src/AoP/Chapter03/ConditionalFusion.agda) derives (3.3–3.5) in a category with chosen coproducts, given a routing arrow that commutes with precomposition and recovers the input when the tag is forgotten. Coproduct fusion moves a final operation into both branches; absorption moves an initial operation through the conditional; equal branches factor through the forgetful arrow. This calculation takes the two routing laws as hypotheses.

## §3.5: concatenation and currying

[Currying](../src/AoP/Chapter03/Currying.agda) implements concatenation as a fold whose result accepts a suffix. [AppendCurriedLayer](../src/AoP/Chapter03/AppendCurriedLayer.agda) derives its two updates from distribution, reassociation, evaluation and currying. The empty branch returns the suffix unchanged. In the cons branch the suffix is paired with the recursive function waiting for it; applying that function and restoring the head yields `a ∷ k ys`. The [tip traversal calculation](../src/AoP/Chapter03/TipTraversal.agda) applies the same idea to trees: the two suffix functions at a fork compose, preserving left-to-right order and eliminating repeated list appends. [TipTraversalWork](../src/AoP/Chapter03/TipTraversalWork.agda) counts newly constructed list cells: `exact` proves one per tip for every tree and every supplied suffix. For tips `1,2,3` and suffix `[4]`, the right subtree supplies `[3,4]` to the left fork. The result `[1,2,3,4]` requires three new cells; the suffix is reused. For a left-leaning tree with four tips, the original traversal constructs four singleton cells and copies prefixes of lengths `1,2,3`, giving ten cells versus four for the suffix traversal. `copy-exact` charges one cons per element of the left operand of append, and `slow-exact` proves that the instrumented original traversal returns both the specified tip list and the predicted count on every tree. These counts exclude tree visits and function applications.
