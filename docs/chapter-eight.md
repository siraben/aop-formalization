# Chapter 8: dynamic programming

## §8.1 Thinning

Thinning retains a subset of candidates. Each original candidate must have a retained candidate that is at least as good under the chosen relation. For example, when the relation is equality, removing the last representative of a value would leave that value uncovered.

| Exercise | Construction and scope |
| --- | --- |
| 8.1 | [ThinIdentity](../src/AoP/ThinIdentity.agda) proves both directions: thinning by equality is exactly extensional equality of the input and output sets. |
| 8.2 | [Thinning](../src/AoP/Thinning.agda) proves reflexivity and transitivity of thinning from the corresponding laws of the comparison relation. |
| 8.3 | `min-after-thin` in [Thinning](../src/AoP/Thinning.agda) lifts a retained minimum to the original set using comparison inclusion and transitivity of the objective. |
| 8.4 | [ThinUnion](../src/AoP/ThinUnion.agda) shows that adding back any subset of the original candidates preserves a thinning. It proves the intermediate union membership inclusion. When the comparisons coincide, taking the same thinning twice witnesses the reverse inclusion up to extensional equality. |
| 8.5 | [SingletonThinning](../src/AoP/SingletonThinning.agda) proves that retaining just `a` is a valid thinning exactly when `a` is a minimum. Under equality the full Boolean set is a valid thinning of itself, yet neither singleton is valid. |
| 8.6 | [FibreThinning](../src/AoP/FibreThinning.agda) proves that thinning the results of one input is unchanged by restricting comparisons to pairs sharing a generating input. The input itself witnesses the extra condition for each coverage edge. |
| 8.7 | [ThinFamily](../src/AoP/ThinFamily.agda) proves (8.4) for indexed families with both power-relator coverage conditions. The converse fails: the union of the Boolean singletons can thin to `{false}` under universal comparison, but any thinning of `{true}` must retain `true`. |

## §8.2 Paths in a layered network

[FibreMinimumPrune](../src/AoP/FibreMinimumPrune.agda) verifies the local pruning step of exercise 8.11. Group candidates by their intermediate state. When each inhabited enabled group has a minimum and cost dominance within a group implies simulation dominance, retaining the group minima is a valid thinning. [FibreMinimumFold](../src/AoP/FibreMinimumFold.agda) carries this pruning step through a cons-list fold: generate intermediate states from the retained tail, keep each enabled group’s minima, then apply the thinning theorem. With the stated base thinning and simulation hypothesis, every final table minimum is a minimum of the full search. The general relator derivation and exercise 8.10’s branching variants remain open.

## §8.3 Implementing thinning

[SnocBump](../src/AoP/SnocBump.agda) implements the snoc-list fold in exercise 8.12. Each new candidate competes with the last survivor. Under universal comparison with ties awarded to the newcomer, the snoc fold on `[false,true]` keeps `true`, while the cons fold keeps `false`. [SnocBumpProof](../src/AoP/SnocBumpProof.agda) proves that reading the result last-element-first agrees with cons thinning on the input read in that same direction. This transfers the cons fold’s coverage and subsequence proofs to the snoc fold.

[AdjacentThin](../src/AoP/AdjacentThin.agda) implements exercise 8.13’s adjacent comparison. Let `bot` dominate the incomparable `l` and `r`. On `[bot,l,r]`, adjacent comparison returns `[bot]` and the text’s fold returns `[bot,r]`. On `[l,r,bot]`, the results are `[l,bot]` and `[bot]` respectively. Thus neither implementation always returns the shorter list. [AdjacentCoverage](../src/AoP/AdjacentCoverage.agda) proves coverage for all inputs: composing each local elimination with the recursive thinning leaves a representative for every original candidate. Its `ordered` theorem also constructs a subsequence witness, so surviving occurrences retain their input order.

[ConnectedBlock](../src/AoP/ConnectedBlock.agda) proves the closure premise for exercise 8.14: any subsequence of a pairwise-comparable block is pairwise comparable. Extending a connected suffix requires only self-comparison of the new head and comparisons between that head and suffix members. [ConnectedMaximum](../src/AoP/ConnectedMaximum.agda) proves the optimized extension criterion under the common-upper-bound hypothesis: comparison with a cached greatest member suffices, and either successful comparison supplies the new greatest member. The minimum-block greedy partition and its fusion remain open.

[LeftMinimumBlock](../src/AoP/LeftMinimumBlock.agda) checks the block laws in exercise 8.15. A block stays admissible when its first element is retained and its tail shortened. For transitive comparison, a new head can be prepended exactly when it dominates the old head. Removing the old head can break admissibility: `[0,2,1]` passes but `[2,1]` fails. [LeftMinimumDirection](../src/AoP/LeftMinimumDirection.agda) checks that a right fold which only extends the first existing block splits this example into `[0,2]|[1]` although the whole input is admissible. [LeftMinimumCount](../src/AoP/LeftMinimumCount.agda) scans from the left and keeps the current block open while its head dominates the next element. It returns a feasible sequence of cuts with the fewest internal boundaries: if the greedy head dominates a competing block’s head, transitivity lets it match every extension by that competitor. [LeftMinimumFusion](../src/AoP/LeftMinimumFusion.agda) fuses the cut sequence with selection of each block’s head. The resulting scan emits a representative at each boundary without constructing a partition; a cons-list fold into functions of the current head computes the same list. [BlockHeadCover](../src/AoP/BlockHeadCover.agda) proves that these heads form a valid thinning: each retained head is an input member, and every input member is dominated by its block’s head.

[HiddenComparison](../src/AoP/HiddenComparison.agda) checks the adversary construction for exercise 8.16. On an antichain, adding just the comparison `u ≤ v` leaves all other ordered comparisons unchanged but removes `v` from the minimal elements of any set containing both points. A deterministic algorithm querying only `Q` must therefore inspect every ordered pair of distinct input values on the antichain, giving `n(n−1)` queries for `n` distinct values. [QueryTrace](../src/AoP/QueryTrace.agda) verifies the adaptive decision-tree step: different outputs require a query on the first execution trace on which the comparison oracles differ. [HiddenTrace](../src/AoP/HiddenTrace.agda) instantiates the tree theorem with Boolean comparison oracles. If `v` is returned on equality and omitted after inserting `(u,v)`, the equality trace contains that exact ordered query. [MinimalQueries](../src/AoP/MinimalQueries.agda) discharges both output conditions for any decision tree that returns exactly the minimal input members for every preorder oracle. Its equality trace therefore contains each ordered pair of distinct members. [TraceCardinality](../src/AoP/TraceCardinality.agda) proves that a trace containing every query of a duplicate-free list is at least as long as that list. It removes one witnessed occurrence at a time, so repeated queries in the trace cannot shorten the bound. [OrderedPairs](../src/AoP/OrderedPairs.agda) constructs the ordered pairs of distinct positions, and proves the list has length `n(n−1)`. Each new position contributes one incoming and one outgoing pair per old position. [PairMembers](../src/AoP/PairMembers.agda) proves that for distinct input values each enumerated pair consists of different input members, so it occurs in the solver’s equality trace. [QuadraticQueries](../src/AoP/QuadraticQueries.agda) proves the pair list has no duplicates for distinct input values and combines these results: `Lower.queries` bounds the equality trace below by `n(n−1)` for any correct deterministic preorder-oracle solver. The bound counts Boolean ordered comparisons.

[SortedSubset](../src/AoP/SortedSubset.agda) proves exercise 8.17: every subsequence of an ordered listing of `X` is an ordered listing of some subset of `X`. Take the subset to be the members of the subsequence. Every comparison required in the smaller list already held in the larger one, so this direction does not require connectedness.

[SortedImage](../src/AoP/SortedImage.agda) verifies equation (8.8) of exercise 8.18. Mapping an ordered listing under the pulled-back comparison gives an ordered listing of the image set. A preimage witness transfers each required comparison and proves the membership equivalence; injectivity is unnecessary. [SortedFilter](../src/AoP/SortedFilter.agda) verifies equation (8.9) for a decidable predicate: the chapter 7 filter yields a subsequence, so exercise 8.17 preserves orderedness, and the survivors are exactly the original members passing the test.

[PolynomialChoices](../src/AoP/PolynomialChoices.agda) implements exercise 8.19 by recursion on polynomial functors. The identity case returns its menu; a constant contributes a singleton. Products enumerate independent choices by a Cartesian product, and sums preserve the input tag. The checked Boolean-product example computes all four output pairs. [ChoiceCoverage](../src/AoP/ChoiceCoverage.agda) proves that an output appears exactly when its shape and constants match the input and each variable position contains a member of its corresponding menu. [InfiniteChoices](../src/AoP/InfiniteChoices.agda) gives an obstruction for exercise 8.20 when arbitrary endofunctors include `T A = Nat → A`. Offering both Boolean values at each position makes every Boolean stream a valid choice. Diagonalization constructs a stream absent from any proposed finite listing, even up to pointwise equality. This argument concerns infinite-position functors; it does not rule out finite-shape traversals.

[NonlinearChoices](../src/AoP/NonlinearChoices.agda) proves exercise 8.21 for `I × I`. The sorted Boolean menus `[false,true]` generate both `(false,true)` and `(true,false)`. These pairs are incomparable in the product order, while any two members of an ordered listing must be comparable. Hence even changing the enumeration order cannot satisfy (8.11).

Exercise 8.22 remains open: derive binary thinning with guards tested before the two branch functions.

## §8.6 Bitonic tours and final exercises

[BitonicTable](../src/AoP/BitonicTable.agda) and [BitonicExample](../src/AoP/BitonicExample.agda) verify a table algorithm and a directed example. The following entries track the tour variants and final exercises.

| Exercise | Remaining construction |
| --- | --- |
| 8.25 | [TourNext](../src/AoP/TourNext.agda) calculates both updates of the book’s `next` pair from the two leg tails. Keeping the left tail gives `(old left next, old first)`; keeping the right tail gives `(old first, old right next)`. The first-layer example gives `(3,2)` and `(2,3)`. The induction for the full table order remains open. |
| 8.26 | [SymmetricTour](../src/AoP/SymmetricTour.agda) proves that swapping both leg endpoints and every interior assignment preserves cost for symmetric edges. Fixing the first interior city on the outward leg removes the duplicate orientation; the reference recurrence then returns a globally optimal tour. [SymmetricTourTable](../src/AoP/SymmetricTourTable.agda) stores a single optimal cell per endpoint pair in each row. Reversing the shared cell provides the other orientation with the same cached price and an optimality proof. |
| 8.27 | [TourVariants](../src/AoP/TourVariants.agda), mode `both`: an interior city may be assigned to both legs. That branch pays both directed extension costs and updates both endpoints. The three-branch reference search certifies a least-cost assignment. |
| 8.28 | [TourVariants](../src/AoP/TourVariants.agda), mode `neither`: skipping an interior city leaves the two endpoints unchanged and costs zero at that step. The search retains the two one-leg alternatives and certifies optimality with fixed start and turnaround cities. [TourVariantExamples](../src/AoP/TourVariantExamples.agda) checks both new choices on three cities: visiting the middle city twice wins at cost 4 when direct legs are expensive; skipping it wins at cost 2 when direct legs are cheap. No table complexity bound is claimed for either variant. |
| 8.29 | [UpsequenceDominance](../src/AoP/UpsequenceDominance.agda) gives the local pruning criterion: retain a suffix at least as long as the discarded one that admits every preceding element it could accept. Taking the same next element preserves order and dominance; skipping it preserves the original comparison. [UpsequenceDecision](../src/AoP/UpsequenceDecision.agda) decides dominance for natural numbers: for two nonempty candidates, compare lengths and heads. The competitor’s own head witnesses any failure of the head comparison. [UpsequenceFrontier](../src/AoP/UpsequenceFrontier.agda) implements the right-to-left fold. Each step retains the skip alternatives, adds the admissible take alternatives, and prunes with `thinlist`; the local thinning certificate covers every candidate generated at that step. [UpsequenceExtensions](../src/AoP/UpsequenceExtensions.agda) proves the take branch is exact: each accepted candidate contributes its extension, and each emitted extension comes from an accepted candidate. [UpsequenceSound](../src/AoP/UpsequenceSound.agda) proves that every final survivor is an ordered subsequence of the original input. [UpsequenceCoverage](../src/AoP/UpsequenceCoverage.agda) proves that every ordered subsequence is dominated by a final survivor: a skip reuses its suffix witness, and a take extends that witness before pruning again. [LongestUpsequence](../src/AoP/LongestUpsequence.agda) scans the survivors for a longest one and combines soundness with global coverage. On `[3,1,2,2]` it returns `[1,2,2]`. The result certifies a maximum-length nondecreasing subsequence for every list of naturals, including the empty input. |
| 8.30 | [RallyDominance](../src/AoP/RallyDominance.agda) proves the one-leg pruning rule for natural fuel and distances: a state with no more stops and at least as much fuel can match a competitor’s pass or capacity-limited refill and still dominate it after travelling the leg. The executable thinning algorithm and minimum-stop proof remain open. |
