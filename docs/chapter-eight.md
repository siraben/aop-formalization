## §8.1 Thinning

[ThinFibreCalculation](../src/AoP/Chapter08/ThinFibreCalculation.agda) spells out the two tests in the universal property of (8.1). For each input and each set the program can return, all retained members must be feasible, and every feasible rival must have a retained representative that dominates it. `introduce` builds a thinning from those two witnesses. Equation (8.3) then permits returning a singleton minimum even when the optimization order implies the thinning order only on pairs feasible at a common input. The winner and its rival share precisely the input needed by this guard.

[ThinningHyloBound](../src/AoP/Chapter08/ThinningHyloBound.agda) checks the coverage calculation in Theorem 8.1. Write `E` for converse membership. The candidate bound `E ∘ Q` says that the retained set contains a representative dominating the rival. To check one layer, split `F (E ∘ Q)` by functoriality, move `F Q` through the rival step by simulation, and apply local coverage. Transitivity composes the two resulting comparisons. Hylomorphism induction then yields coverage for the whole fold. [ThinLayerFusion](../src/AoP/Chapter08/ThinLayerFusion.agda) supplies the separate feasibility calculation. Reading a member after generating and pruning gives a member of the generated set; unpacking generation shows it is legal. Fold fusion lifts this test from one layer to the whole input. For coverage, an exhaustive rival belongs to the generated set, so local thinning supplies its representative. `Result.theorem` combines both fold-level inclusions with the thinning universal property. The fold fusion and induction rules are explicit hypotheses.

Thinning retains a subset of candidates. Each original candidate must have a retained candidate that is at least as good under the chosen relation. For example, when the relation is equality, removing the last representative of a value would leave that value uncovered.

## §8.2 Paths in a layered network

**Calculate what a table row must remember.** Suppose suffix path `q` can replace suffix path `p`: they begin at the same vertex and `cost q ≤ cost p`. Prepending vertex `v` preserves the comparison:

```text
cost (via v q)
= weight v (head q) + cost q     path-cost equation
= weight v (head p) + cost q     same starting vertex
≤ weight v (head p) + cost p     addition preserves the suffix bound
= cost (via v p)                 path-cost equation backwards
```

This identifies the safe pruning rule: keep a cheapest suffix *for each starting vertex*. Dropping the equal-head premise would leave two different incoming edge charges on the second line. The example below shows that they can reverse the comparison.

Choose one vertex from each nonempty layer to minimize the sum of adjacent edge weights. [LayeredCostFold](../src/AoP/Chapter08/LayeredCostFold.agda) derives the paired fold that stores a nonempty path alongside its cost. A singleton costs zero. Prepending a vertex adds the edge weight to the stored cost; `exact` proves the fold returns the original path and its specified cost. In the three-layer example `{root}`, `{west,east}`, `{goal}`, the two suffixes cost 2 and 5. Prepending `root` adds 10 and 1 respectively, reversing the ranking: the complete paths cost 12 and 6. This is why pruning by suffix cost must also account for the suffix’s starting vertex. [LayeredRowChoice](../src/AoP/Chapter08/LayeredRowChoice.agda) scans a nonempty list of suffix paths for a fixed new vertex. `choose` returns a listed suffix minimizing the cost including its incoming edge; `complete` extends the bound to any rival represented by a no-more-expensive suffix with the same head. In the example, `Trace.result` selects the east suffix. [LayeredPathMinimum](../src/AoP/Chapter08/LayeredPathMinimum.agda) builds the table backwards from singleton paths in the last layer. Each row stores a legal path for its starting vertex and bounds every legal rival from that start. `solve` minimizes across the first layer, proving the returned path is globally optimal for finite nonempty layers and natural edge weights. The checked example returns `root → east → goal`. [LayeredHeadCache](../src/AoP/Chapter08/LayeredHeadCache.agda) verifies the book’s final `(path, head, cost)` representation separately: prepending reads the cached head and cost, then stores the new vertex and updated cost. `exact` identifies the cached fields with the path specification. The east suffix carries `(east, 5)` and prepending the root updates those fields to `(root, 6)`. [LayeredCachedRow](../src/AoP/Chapter08/LayeredCachedRow.agda) scans certified suffix cells using `weight incoming start + score` as the comparison key. It extends the winning cell once; its head and score certificates justify using that cell as input to another row. `beats` transfers the comparison back to path costs for every listed rival. The example returns 6 even though the west suffix alone costs less. [LayeredCachedTable](../src/AoP/Chapter08/LayeredCachedTable.agda) uses that scan at every layer. Its invariant assigns every legal rival a listed path with the same first vertex and no greater cost. Prepending a vertex therefore adds the same charge to both. The final scan compares stored scores and returns the original `Answer`: a legal path with a cost bound against every legal path. `Trace.route` checks the full cached solver on `root → east → goal`.

[FibreMinimumPrune](../src/AoP/Chapter08/FibreMinimumPrune.agda) verifies the local pruning step of exercise 8.11. Group candidates by their intermediate state. When each inhabited enabled group has a minimum and cost dominance within a group implies simulation dominance, retaining the group minima is a valid thinning. [FibreMinimumFold](../src/AoP/Chapter08/FibreMinimumFold.agda) carries this pruning step through a cons-list fold: generate intermediate states from the retained tail, keep each enabled group’s minima, then apply the thinning theorem. With the stated base thinning and simulation hypothesis, every final table minimum is a minimum of the full search. [FibrePowerThinning](../src/AoP/Chapter08/FibrePowerThinning.agda) proves the one-layer law with the book’s power relator, allowing a selection among tied minima. Each selected result comes from an enabled state, and each enabled state supplies a selected minimum that can replace a rival from that same state. A minimum of the selected set is therefore also a minimum of the reachable set. [InitialFibrePruning](../src/AoP/Chapter08/InitialFibrePruning.agda) iterates this calculation through any initial algebra on `Fun`. Fold into the subtype of inputs equipped with certified child tables. At each layer compose fibre pruning with the generation simulation; fold fusion identifies the projected input with the original input. `optimum` transfers each final table minimum to the full search. [FibreGeneration](../src/AoP/Chapter08/FibreGeneration.agda) derives one-layer generation coverage from monotonicity of the transition on the converse comparison. Each exhaustive child result has a retained representative; splitting the lifted composition finds a layer of such representatives, and transition monotonicity matches the rival parent. [FibreGenerationTransport](../src/AoP/Chapter08/FibreGenerationTransport.agda) transports a lifted relation across the projection that forgets each child’s certificate. [CertifiedFibreLayer](../src/AoP/Chapter08/CertifiedFibreLayer.agda) applies generation to the certified children and transports both subset and coverage witnesses back to the underlying inputs. [FibreFoldRefinement](../src/AoP/Chapter08/FibreFoldRefinement.agda) connects the generation comparison at `map val t` to the constructor. Enabled states come from `S₂` applied to the retained child results. `ready` reassociates the intermediate witnesses and uses the exhaustive fold equation in both directions. `Run.optimum` concludes that every minimum of a table satisfying the fibre-selection step is a global minimum. The theorem assumes the stated relator laws, transition monotonicity and fold equations; it requires neither a separate generation hypothesis nor unique minima. [FibreTieTrace](../src/AoP/Chapter08/FibreTieTrace.agda) checks the tie case: west has a red and a blue route of cost 2, east has a green route of cost 5. Keeping blue and green covers both stations; `best` certifies blue against all three routes, including the discarded red route. [BranchNetwork](../src/AoP/Chapter08/BranchNetwork.agda) treats the two branching variants of 8.10 with natural additive costs. A fork connects one parent to two child starts, and both child routes must be supplied. Internal labels can constrain available forks (`J = A`); a singleton label type gives unlabelled forks. Once a fork is fixed, either child route can be replaced by a cheaper one at the same start. `lift` proves this for one layer and `Table.correct` iterates the coverage proof over the tree, assuming valid local pruning at each layer. [BranchNetworkTrace](../src/AoP/Chapter08/BranchNetworkTrace.agda) checks a root fork of cost 3 whose two child forks each cost 1 or 4. Replacing the left and then the right costly route gives `3 + 4 + 4 = 11`, `3 + 1 + 4 = 8`, and `3 + 1 + 1 = 5`. Its `minimum` proof bounds every feasible route in this network by comparing the children separately.

## §8.3 Implementing thinning

**Derive the list update.** Write `U ≼ V` here for “the retained list `U` thins the original list `V`”: each survivor came from `V`, and each member of `V` is dominated by some survivor. Suppose `ys = thinlist xs`. The fold step needs `thinlist (x ∷ xs) ≼ x ∷ xs`. Factor this obligation through the candidate list `x ∷ ys`:

```text
bump x ys ≼ x ∷ ys       local elimination: drop a head only with a dominating witness
          ≼ x ∷ xs       lift the suffix thinning; x represents itself
```

Transitivity composes the two coverage witnesses. If `ys` starts with `y`, compare `x` with `y`: retain `x` in place of `y` when `x` dominates it, retain `y` alone when it dominates `x`, or keep both. The empty suffix just takes the singleton `[x]`. This proves coverage without assuming every pair is comparable or promising the smallest possible survivor list. [Bump](../src/AoP/Chapter08/Bump.agda) checks both inclusions implicit in the thinning specification, and `ordered` records the actual surviving positions as a subsequence.

**Comparison count.** The suffix of a nonempty list has a survivor whenever that suffix itself is nonempty: its first input member needs a representative. So for a list of length `n` the call count satisfies `C(0) = C(1) = 0` and `C(n+2) = 1 + C(n+1)`. `exact-work` proves `C(n+1) = n` even if the comparison always chooses to retain both candidates. This counts calls to the supplied comparison, independently of the cost of deciding dominance.

The [connected thinning guide](connected-thinning.md) follows exercise 8.14 from the minimum-block specification through the streaming fold and its worked trace.

[SnocBump](../src/AoP/Chapter08/SnocBump.agda) implements the snoc-list fold in exercise 8.12. Each new candidate competes with the last survivor. Under universal comparison with ties awarded to the newcomer, the snoc fold on `[false,true]` keeps `true`, while the cons fold keeps `false`. [SnocBumpProof](../src/AoP/Chapter08/SnocBumpProof.agda) proves that reading the result last-element-first agrees with cons thinning on the input read in that same direction. This transfers the cons fold’s coverage and subsequence proofs to the snoc fold.

[AdjacentThin](../src/AoP/Chapter08/AdjacentThin.agda) implements exercise 8.13’s adjacent comparison. Let `bot` dominate the incomparable `l` and `r`. On `[bot,l,r]`, adjacent comparison returns `[bot]` and the text’s fold returns `[bot,r]`. On `[l,r,bot]`, the results are `[l,bot]` and `[bot]` respectively. Thus neither implementation always returns the shorter list. [AdjacentCoverage](../src/AoP/Chapter08/AdjacentCoverage.agda) proves coverage for all inputs: composing each local elimination with the recursive thinning leaves a representative for every original candidate. Its `ordered` theorem also constructs a subsequence witness, so surviving occurrences retain their input order.

[ConnectedBlock](../src/AoP/Chapter08/ConnectedBlock.agda) proves the closure premise for exercise 8.14: any subsequence of a pairwise-comparable block is pairwise comparable. Extending a connected suffix requires only self-comparison of the new head and comparisons between that head and suffix members. [ConnectedMaximum](../src/AoP/Chapter08/ConnectedMaximum.agda) proves the optimized extension criterion under the common-upper-bound hypothesis: comparison with a cached greatest member suffices, and either successful comparison supplies the new greatest member. [LongestConnectedBlock](../src/AoP/Chapter08/LongestConnectedBlock.agda) computes the first greedy block for reflexive `Q` with decidable comparability. `valid?` tests a new head against the suffix; `first` returns a connected prefix, the remaining input, and a proof that every connected prefix lies inside the chosen one. [ConnectedBlockExchange](../src/AoP/Chapter08/ConnectedBlockExchange.agda) proves that replacing a rival’s first block with the greedy prefix leaves a remainder coverable by one fewer block: any extra consumed letters merely remove or shorten existing blocks. [ConnectedPartitionMinimum](../src/AoP/Chapter08/ConnectedPartitionMinimum.agda) iterates this exchange, starting with the all-singletons budget. `solve` returns a partition witness and a proof that its block count is at most every rival’s budget; `block-list` extracts the actual blocks. [ConnectedPartitionThin](../src/AoP/Chapter08/ConnectedPartitionThin.agda) computes one least member of each chosen block under transitivity. Its `correct` proof splits each input membership witness at the block boundary to find a retained representative, and shows that every representative belongs to the input. `thinlist` applies this selection to the minimum-block partition. [ConnectedPartitionTrace](../src/AoP/Chapter08/ConnectedPartitionTrace.agda) checks `[left, low, right]`, with `low` below both endpoints and the endpoints incomparable. The longest first block is `[left, low]`; the second is `[right]`. The minimum count is two and the block minima are `[low, right]`. [ConnectedPartitionFusion](../src/AoP/Chapter08/ConnectedPartitionFusion.agda) fuses a streaming partition with selection. The active block carries its least member; `commute` shows that saving only that member on closing a block agrees with saving the whole block and projecting later. `equation` proves this for the complete snoc fold. [ConnectedStreamInvariant](../src/AoP/Chapter08/ConnectedStreamInvariant.agda) proves all active and completed blocks are connected. At a cut, `barrier` shows that adjoining the rejected letter would violate pairwise comparability. [ConnectedFastDecision](../src/AoP/Chapter08/ConnectedFastDecision.agda) replaces the full block extension test by a single comparison with its certified greatest member, under the common-upper-bound hypothesis. `same-cut` proves that both tests decide the same branch. [ConnectedCutLongest](../src/AoP/Chapter08/ConnectedCutLongest.agda) turns a rejected extension into a longest-prefix certificate in input order: every competing prefix either stops inside the block or contains the entire rejected extension, contradicting prefix closure. [ConnectedReverseCut](../src/AoP/Chapter08/ConnectedReverseCut.agda) transports both connectedness and the failed extension across reversal, yielding a longest-prefix certificate in input order for a reverse-stored block and any subsequent suffix. [LongestPrefixUnique](../src/AoP/Chapter08/LongestPrefixUnique.agda) proves that any two longest-prefix certificates for the same input and predicate give identical blocks and suffixes: mutual maximality gives prefix antisymmetry, then cancellation gives the suffix equality. [GreedyBoundaryAgreement](../src/AoP/Chapter08/GreedyBoundaryAgreement.agda) iterates this uniqueness through a complete sequence of cuts. `ConnectedPartitionMinimum.Result.boundaries` certifies every cut returned by the reference solver, and `agrees` identifies any other certified sequence with its extracted block list. [StreamingCutSequence](../src/AoP/Chapter08/StreamingCutSequence.agda) constructs that sequence from the streaming fold. Its invariant accepts a certificate for the still-open block and remaining input, and prepends the certificates for all closed blocks. Closing the last block gives `complete`; `agrees` proves that restoring input order yields exactly the reference solver’s block list for every input. [StreamingPartitionMinima](../src/AoP/Chapter08/StreamingPartitionMinima.agda) connects those boundaries to the fused program’s output: `certified` pairs every reference block, in order, with a least member returned by the streaming fold. Tied minima may have different representatives. [ConnectedFusionTrace](../src/AoP/Chapter08/ConnectedFusionTrace.agda) computes the streaming states for `[left, low, right]`: after `low` the active block is stored as `[low, left]` with minimum `low`; on `right` the fold saves `low` and starts `[right]`. Although `right` is comparable with `low`, it is incomparable with `left`, forcing the cut. Closing the stream returns `[low, right]`.

[LeftMinimumBlock](../src/AoP/Chapter08/LeftMinimumBlock.agda) checks the block laws in exercise 8.15. A block stays admissible when its first element is retained and its tail shortened. For transitive comparison, a new head can be prepended exactly when it dominates the old head. Removing the old head can break admissibility: `[0,2,1]` passes but `[2,1]` fails. [LeftMinimumDirection](../src/AoP/Chapter08/LeftMinimumDirection.agda) checks that a right fold which only extends the first existing block splits this example into `[0,2]|[1]` although the whole input is admissible. [LeftMinimumCount](../src/AoP/Chapter08/LeftMinimumCount.agda) scans from the left and keeps the current block open while its head dominates the next element. It returns a feasible sequence of cuts with the fewest internal boundaries: if the greedy head dominates a competing block’s head, transitivity lets it match every extension by that competitor. [LeftMinimumFusion](../src/AoP/Chapter08/LeftMinimumFusion.agda) fuses the cut sequence with selection of each block’s head. The resulting scan emits a representative at each boundary without constructing a partition; a cons-list fold into functions of the current head computes the same list. [BlockHeadCover](../src/AoP/Chapter08/BlockHeadCover.agda) proves that these heads form a valid thinning: each retained head is an input member, and every input member is dominated by its block’s head.

[HiddenComparison](../src/AoP/Chapter08/HiddenComparison.agda) checks the adversary construction for exercise 8.16. On an antichain, adding just the comparison `u ≤ v` leaves all other ordered comparisons unchanged but removes `v` from the minimal elements of any set containing both points. A deterministic algorithm querying only `Q` must therefore inspect every ordered pair of distinct input values on the antichain, giving `n(n−1)` queries for `n` distinct values. [QueryTrace](../src/AoP/Chapter08/QueryTrace.agda) verifies the adaptive decision-tree step: different outputs require a query on the first execution trace on which the comparison oracles differ. [HiddenTrace](../src/AoP/Chapter08/HiddenTrace.agda) instantiates the tree theorem with Boolean comparison oracles. If `v` is returned on equality and omitted after inserting `(u,v)`, the equality trace contains that exact ordered query. [MinimalQueries](../src/AoP/Chapter08/MinimalQueries.agda) discharges both output conditions for any decision tree that returns exactly the minimal input members for every preorder oracle. Its equality trace therefore contains each ordered pair of distinct members. [TraceCardinality](../src/AoP/Chapter08/TraceCardinality.agda) proves that a trace containing every query of a duplicate-free list is at least as long as that list. It removes one witnessed occurrence at a time, so repeated queries in the trace cannot shorten the bound. [OrderedPairs](../src/AoP/Chapter08/OrderedPairs.agda) constructs the ordered pairs of distinct positions, and proves the list has length `n(n−1)`. Each new position contributes one incoming and one outgoing pair per old position. [PairMembers](../src/AoP/Chapter08/PairMembers.agda) proves that for distinct input values each enumerated pair consists of different input members, so it occurs in the solver’s equality trace. [QuadraticQueries](../src/AoP/Chapter08/QuadraticQueries.agda) proves the pair list has no duplicates for distinct input values and combines these results: `Lower.queries` bounds the equality trace below by `n(n−1)` for any correct deterministic preorder-oracle solver. The bound counts Boolean ordered comparisons.

[SortedSubset](../src/AoP/Chapter08/SortedSubset.agda) proves exercise 8.17: every subsequence of an ordered listing of `X` is an ordered listing of some subset of `X`. Take the subset to be the members of the subsequence. Every comparison required in the smaller list already held in the larger one, so this direction does not require connectedness.

[SortedImage](../src/AoP/Chapter08/SortedImage.agda) verifies equation (8.8) of exercise 8.18. Mapping an ordered listing under the pulled-back comparison gives an ordered listing of the image set. A preimage witness transfers each required comparison and proves the membership equivalence; injectivity is unnecessary. [SortedFilter](../src/AoP/Chapter08/SortedFilter.agda) verifies equation (8.9) for a decidable predicate: the chapter 7 filter yields a subsequence, so exercise 8.17 preserves orderedness, and the survivors are exactly the original members passing the test.

[PolynomialChoices](../src/AoP/Chapter08/PolynomialChoices.agda) implements exercise 8.19 by recursion on polynomial functors. The identity case returns its menu; a constant contributes a singleton. Products enumerate independent choices by a Cartesian product, and sums preserve the input tag. The checked Boolean-product example computes all four output pairs. [ChoiceCoverage](../src/AoP/Chapter08/ChoiceCoverage.agda) proves that an output appears exactly when its shape and constants match the input and each variable position contains a member of its corresponding menu. [InfiniteChoices](../src/AoP/Chapter08/InfiniteChoices.agda) gives an obstruction for exercise 8.20 when arbitrary endofunctors include `T A = Nat → A`. Offering both Boolean values at each position makes every Boolean stream a valid choice. Diagonalization constructs a stream absent from any proposed finite listing, even up to pointwise equality. [FinitaryShapeChoices](../src/AoP/Chapter08/FinitaryShapeChoices.agda) gives a positive result even with infinitely many shapes and unbounded arities. Each individual shape supplies a natural-number arity. `listcp` keeps the input shape and forms a Cartesian product of its finite menus; the nullary product contains one empty tuple. `sound` and `complete` identify the listed outputs with precisely the same-shape tuples whose entries belong to their menus. [NonlinearChoices](../src/AoP/Chapter08/NonlinearChoices.agda) proves exercise 8.21 for `I × I`. The sorted Boolean menus `[false,true]` generate both `(false,true)` and `(true,false)`. For exercise 8.22, [GuardedBinaryThin](../src/AoP/Chapter08/GuardedBinaryThin.agda) proves a cons-list version for two deterministic branches guarded on the input state. [GuardLoss](../src/AoP/Chapter08/GuardLoss.agda) shows why monotonicity of the branch functions alone is insufficient: thinning `{0,1}` to `{0}` preserves a minimum, but when both identity branches require a positive input, the exhaustive next set contains `1` and the pruned next set is empty.

## §8.4 The knapsack problem

The [worked knapsack derivation](knapsack.md) follows one item through the take stream, skip stream, merge, and thinning, then explains how the winning summary determines an original-item selection.

[Knapsack](../src/AoP/Chapter08/Knapsack.agda), [KnapsackSearch](../src/AoP/Chapter08/KnapsackSearch.agda), and [KnapsackFrontier](../src/AoP/Chapter08/KnapsackFrontier.agda) treat feasible selections, optimal search, and pruning. [KnapsackGuardStep](../src/AoP/Chapter08/KnapsackGuardStep.agda) derives the guarded branch condition for natural weights and values: a lighter, at-least-as-valuable representative can match either taking or skipping the next item. Value alone fails at capacity 3: `(weight,value) = (1,4)` can take `(2,3)` and reach value 7, whereas `(3,5)` must skip and remains at 5. [KnapsackSortedBranches](../src/AoP/Chapter08/KnapsackSortedBranches.agda) proves that taking an item preserves descending value order: adding its value preserves comparisons, and filtering overweight results preserves the surviving order. For the same capacity and next item, extending `[(3,5),(1,4),(0,0)]` retains `[(3,7),(2,3)]`. The skip stream keeps the original order. [KnapsackMerge](../src/AoP/Chapter08/KnapsackMerge.agda) merges the take and skip streams, preserving descending order and membership in both directions. In the example the merged values are `7,5,4,3,0`. [KnapsackSortedTable](../src/AoP/Chapter08/KnapsackSortedTable.agda) folds merging and thinning over all items and proves every resulting table remains sorted. The sample sweep keeps `[(3,7),(1,4),(0,0)]`. [KnapsackStreamLaw](../src/AoP/Chapter08/KnapsackStreamLaw.agda) proves both membership directions before thinning: each merged candidate comes from a previous pack and an enabled take or skip, and every such choice occurs. [KnapsackTableCoverage](../src/AoP/Chapter08/KnapsackTableCoverage.agda) proves the whole-fold invariant: every survivor has a legal take/skip history, and every legal history is represented by a survivor at least as valuable and no heavier. Skipping all items supplies a history even at capacity zero. [KnapsackHead](../src/AoP/Chapter08/KnapsackHead.agda) extracts the first survivor: the all-skip history rules out an empty table, and descending value order puts the head above every legal history’s representative. `Solver.solve` returns the optimal summary and its take/skip witness. For `[(2,3),(3,5),(1,4)]` at capacity 3 it returns `(3,7)`. [KnapsackPackBridge](../src/AoP/Chapter08/KnapsackPackBridge.agda) turns that history back into a selection of original input items. Its `solve-pack` has the same `Best` specification as exhaustive search for any item type with natural weights and values. Replaying by input position keeps distinct items distinguishable even when their summaries coincide. [KnapsackItemExample](../src/AoP/Chapter08/KnapsackItemExample.agda) checks the actual selected names: at capacity 4, `red` and `blue`, each weighing 2 and worth 3, together beat `heavy`, which weighs 3 and is worth 5.

## §8.5 The paragraph problem

**Calculate the objective from the layout state.** Let `m` be the margin, `k` the number of completed lines, and `l` the width of the current line. Charge unused space on completed lines only. Let `flat` be the width of all the words written on one line, counting one space between adjacent words. [ParagraphSnocWaste.balance](../src/AoP/Chapter08/ParagraphSnocWaste.agda) gives the invariant

```text
waste + flat = k * (m + 1) + l.
```

To see where the `+ 1` comes from, append a word of width `w`. On either branch `flat` grows by `1 + w`. Gluing the word leaves `waste` unchanged and increases `l` by the same amount (provided the line fits). Breaking instead adds `m − l` to `waste`, increments `k`, and sets the new width to `w`. The left side after the break becomes

```text
(m − l) + waste + flat + 1 + w
= (m − l) + k * (m + 1) + l + 1 + w     previous invariant
= (k + 1) * (m + 1) + w                  since l ≤ m.
```

Thus layouts of the same words can be compared using `k` and `l`, since `flat` is fixed. At margin 6 the words `[2,2,1]` have `flat = 7`. Joining the first two and breaking before the last gives `(k,l) = (1,1)`, hence waste `7 + 1 − 7 = 1`. Breaking after the first gives `(1,4)`, hence waste `4`. [ParagraphSnocTrace](../src/AoP/Chapter08/ParagraphSnocTrace.agda) checks the line decisions and both costs. This calculation concerns additive waste; squaring each line’s slack changes the objective.

The objective matters. [ParagraphSquareFailure](../src/AoP/Chapter08/ParagraphSquareFailure.agda) checks two layouts of word widths `[3,2,2,5]` at margin 6. Greedy closes lines of widths 6 and 2, leaving gaps 0 and 4; breaking earlier closes widths 3 and 5, leaving gaps 3 and 1. Both layouts have additive waste 4, but the squared penalties are 16 and 10 respectively. Thus the greedy rule in 8.24 fails for the section’s squared objective.
